01 / Challenge

A decryption oracle that counts bits

The service generates a fresh 2048-bit RSA modulus, chooses a random plaintext m, and publishes c = m^e mod n. Submitting the exact integer m prints the flag. Every other integer is decrypted, but the service reveals only the result's population count.

e = 65537
n = p * q
d = pow(e, -1, (p-1)*(q-1))
m = secrets.randbelow(n)
c = pow(m, e, n)

A single Hamming weight carries little positional information. Raw RSA's multiplicative structure lets us ask for the Hamming weights of a carefully related sequence instead.

02 / Oracle construction

Ask for chosen multiples of the secret

For a public multiplier r, submit x = c * r^e mod n. Decryption returns m*r mod n, so the response is HW(m*r mod n).

x^d = (m^e * r^e)^d = m*r mod n

Set r = 2^i and define a_i = m*2^i mod n. Consecutive terms obey:

a_(i+1) = 2*a_i       when a_i < n/2
a_(i+1) = 2*a_i - n   when a_i >= n/2

The lower-half case is a left shift, so HW(a_(i+1)) = HW(a_i) exactly. A changed weight proves that modular reduction occurred and that a_i occupied the upper half.

03 / Binary expansion

Each half decision is one digit of m/n

The doubling map shifts the binary expansion of the fraction m/n. The upper-half decision at step i is its next binary digit:

m/n = 0.b_0 b_1 b_2 ...
b_i = floor(2*a_i/n)

After L = bit_length(n) decisions, a prefix P gives the integer interval

ceil(n*P / 2^L) <= m <= ceil(n*(P+1) / 2^L) - 1.

Since n < 2^L, the interval's width is below one. A correct prefix therefore identifies the exact plaintext.

04 / Collision handling

Use the modular negative as the second witness

Reduction may occasionally preserve Hamming weight. Query the modular negative z_i = n-a_i as well. It lies in the opposite half, so exactly one of the positive and negative doubling steps reduces.

The winning instance left only 18 erasures. Sparse streams for 3*m*2^i mod n, queried only beside those positions, constrain the same binary prefix and prune each wrong branch. One secondary position also collided, so one r = 5 constraint completed the recovery.

At each search depth, the known prefix bounds frac(r*2^i*m/n). Once that interval lies wholly below or above one half, the secondary bit is fixed and an inconsistent branch is discarded. The solver explored 2067 nodes for a 2048-bit answer.

05 / Remote engineering

Skip negative queries whose answer is implied

The service spends most of its time on RSA private operations. The exploit first collects all positive weights and asks for HW(n-m) once. When a positive count changes, the negative side did not reduce, so its next weight is equal to its current weight and requires no query. A fresh negative weight is requested only after an equal positive transition.

2049 positive observations
1030 adaptive negative observations
18 sparse r=3 collision checks
 1 sparse r=5 fallback

This brought the main workload down from roughly 4100 to 3079 oracle operations and allowed the exploit to finish within the live instance lifetime.

06 / Candidate verification

Accept only a complete orbit match

At 2048 decisions, each surviving prefix is converted into its integer interval. The solver accepts only a singleton interval, then regenerates the complete modular-doubling orbit and compares every Hamming weight with the transcript. The unique surviving integer is submitted on the original connection.

low  = ceil(n * prefix / 2**L)
high = ceil(n * (prefix + 1) / 2**L) - 1

assert low == high
assert observed_weights == orbit_weights(low)
