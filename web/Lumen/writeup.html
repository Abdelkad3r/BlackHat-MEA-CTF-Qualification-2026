00 The target

What is worth stealing, and where it lives

The brief is an ordered checklist: find the reflection, get it to run despite the CSP, and convince the operator to hand over what's in their browser.

A single index.php serves four pages via ?p= (home, view, report, trace). The valuable data never touches the server — a headless Chromium operator seeds the flag into localStorage and then opens whatever URL you report:

bot.js the operator
// seed on one page, then open the reported URL on the same origin
await page.goto(SELF + '/?p=home', { waitUntil: 'load' });
await page.evaluate((f) => localStorage.setItem('flag', f), FLAG);
...
await page.goto(target, { waitUntil: 'load' });
await page.waitForTimeout(4000);

localStorage is origin-scoped, so the flag is readable from any page on 127.0.0.1:5000 — but only by JavaScript running on that origin. The flag is never reflected in any HTML response, which rules out every scriptless trick (dangling-markup, CSS exfiltration): there is nothing in the markup to steal. Script execution is mandatory. And every response is locked down:

response header · every page
Content-Security-Policy: default-src 'none'; script-src 'nonce-<16 random bytes>';
                         style-src 'nonce-<same>'; img-src 'self'; base-uri 'none';
01 The reflection

One raw < smuggled across a parameter boundary

?p=view reflects a missing document's path unescaped. The guard, clean(), runs before the sink is assembled:

index.php · ?p=view
function clean($s){
  if (preg_match('/%3c/i', $s)) return false;      // reject encoded '<'
  return htmlspecialchars($s, ENT_QUOTES);
}
$dir  = clean($_GET['dir']);
$file = clean($_GET['file']);
$path = urldecode($dir . $file);                   // decode AFTER cleaning + concat
...
echo '... 404 - no document at <b>'.$path.'</b> ...';  // echoed RAW

Because htmlspecialchars runs first and urldecode runs last, a percent-encoded < passes the escaper untouched and only becomes real at the decode. The author saw that and blocked %3c — but the check is per-parameter while the decode is on the concatenation. Split the sequence across the boundary and neither value ever contains %3c:

$_GET valueclean()?after htmlspecialchars
dirdocs/%3passdocs/%3
filec…payload…passc…payload…
concatdocs/%3c…
urldecodedocs/<…
rendered raw<b>docs/<…</b>

Two decodes hit our bytes — PHP's automatic $_GET decode and the explicit urldecode — with htmlspecialchars in between. So every literal we want in the output is double-encoded on the wire: it arrives at the escaper as an inert %XX and is only reconstituted by the final decode (which also carries " ' > straight through). To inject HTML string P after the smuggled <:

encoding solve/gen.py
$_GET['dir']  = "docs/%3"              wire: dir  = docs%2F%253
$_GET['file'] = "c" + urlencode(P)    wire: file = c + urlencode(urlencode(P))
                                      =>  final $path = "docs/<" + P

The boundary yields exactly one < — one element. That is all an event handler needs.

02 Dropping the CSP

The header loses a race it didn't know it was in

The policy is not bypassable client-side: no 'unsafe-inline' (so event handlers and javascript: are dead), a fresh random_bytes nonce per response (unguessable), the nonce sitting in <head> before the reflection (so dangling-markup can't steal it forward), and default-src 'none' killing frames and objects. The weakness is one level down — in how the header is emitted. Read the runner:

application/run
exec php -d display_errors=1 -d output_buffering=0 -d max_input_vars=1000 \
     -d variables_order=GPCS -S 0.0.0.0:5000 -t /app/public
  • max_input_vars=1000 — exceeding it prints a warning during request startup / input parsing, before index.php runs.
  • display_errors=1 + output_buffering=0 — that warning is written to the body immediately, unbuffered.
  • so the body — and the HTTP headers — are flushed before index.php reaches its first line and calls header("Content-Security-Policy: …").

Send more than 1000 GET parameters and the CSP is simply never set:

curl -i · payload request (>1000 params) no CSP header
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Referrer-Policy: no-referrer
                              <-- Content-Security-Policy is GONE

<b>Warning</b>: PHP Request Startup: Input variables exceeded 1000. …
<b>Warning</b>: Cannot modify header information - headers already sent
        in <b>/app/public/index.php</b> on line <b>3</b>
<!doctype html> …

Order the query so p, dir, file come first (PHP registers the first 1000 before bailing) and pad with a thousand throwaway z1=1&z2=1&…. With the CSP gone, the single injected element becomes an ordinary event-handler XSS:

03 Handing it over

A same-origin store as the exfil channel

The onerror reads the operator's localStorage and posts it to ?p=trace, a same-origin key/value store — a channel that would satisfy even img-src 'self'. GET …&note=DATA writes; a later GET … (no note) reads it back:

index.php · ?p=trace
if (preg_match('/^[A-Za-z0-9]{8,64}$/', $id)) {
  if (isset($_GET['note']))  file_put_contents($t, substr($_GET['note'],0,1024));  // write
  elseif (is_file($t))       echo '...<pre>'.htmlspecialchars(file_get_contents($t)).'</pre>...'; // read
}

?p=report accepts any http(s) URL and the bot localises it to 127.0.0.1:5000 + path + query + hash, preserving our whole query string. Submit, wait for the visit, read the trace:

04 Takeaways

What the puzzle is really about

A CSP is only as trustworthy as the code path that emits it. The policy was perfect; the bug was that header() can lose a race to unbuffered startup output. display_errors=1 with output_buffering=0 turns any pre-execution notice into a security-header bypass. Set headers you cannot afford to lose at the web-server layer, and keep display_errors off in production.

Canonicalise, then validate, then use. clean() inspected each parameter before the urldecode and concatenation that built the sink, so its %3c check ran on the wrong bytes. Never validate a different representation than the one you emit.

Convenience features are exfil sinks. The trace store made dropping the CSP unnecessary for the exfiltration — only for the execution. Same-origin write/read primitives defeat img-src 'self' by construction.
